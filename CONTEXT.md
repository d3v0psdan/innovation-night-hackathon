# Context

**The ask**: an onboarding flow that asks a founder a few questions and lands them on the one ScaleupMap tool they need first.

**Judges care about**
- How well users land in the right place
- Ease of use
- The demo

## Steps

### Must (2h)
- [ ] Load the sponsor facts and the goal to destination table with `/scaleupmap` (5 min, total 0:05)
- [ ] Write users, questions, routing and demo story to PLAN.md with `/plan-feature` (10 min, total 0:15)
- [ ] Add journey stage, goal and team size questions end to end with `/onboarding-step` (30 min, total 0:45)
- [ ] Build OnboardingRouter from the goal table with a dataset test with `/routing-rule` (20 min, total 1:05)
- [ ] Build the question screen and the "because you said" landing stub pages with `/design-screen` (30 min, total 1:35)
- [ ] Seed one founder per destination plus one fresh user with `/demo-seed` (10 min, total 1:45)
- [ ] Write PITCH.md and backup screenshots with `/pitch-prep` (15 min, total 2:00)

### Should
- [ ] Add a feature test per endpoint and one browser happy path with `/write-tests` (20 min)
- [ ] Show step progress and a back link on the question screen with `/design-screen` (15 min)
- [ ] Run the ux-reviewer agent on the question screen and fix the top 3 (15 min)

### Could
- [ ] Use journey stage as a tiebreak so two founders with the same goal land differently with `/routing-rule` (15 min)
- [ ] Let a founder change answers from the landing page with `/onboarding-step` (15 min)
